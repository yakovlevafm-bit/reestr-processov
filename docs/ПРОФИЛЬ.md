# Профиль ведомства

Всё, что знает о конкретном органе власти, лежит в `profiles/<id>/`. Ядро (`lib/`, `server.js`, `reestr.js`)
не содержит названий ведомств, подразделений и отраслевых слов. Пример — `profiles/demo-kultura/`
(вымышленный комитет по культуре и туризму): скопируйте его и замените содержимое.

Какой профиль включён: переменная `REESTR_PROFILE`, иначе ключ `profile` в `data/config.json`, иначе
единственный установленный профиль (демо-профили не считаются), иначе первый по алфавиту.

## profile.json

| Раздел | Что внутри |
|---|---|
| `id` | идентификатор, совпадает с именем папки |
| `org` | название: полное, короткое, для заголовка (`ui`), для меню (`navSub`), в родительном и предложном падежах, вид органа (`kindNom`, `kindGen`, `kindPrep`), отрасль, префикс идентификаторов процессов (`idPrefix`: `ДКТ` → `ДКТ-9`) |
| `people` | должность и инициалы руководителя, контакт для писем — только для шаблонов документов |
| `files` | `registry` — путь к реестру по умолчанию для `node reestr.js import` |
| `departments` | `empty` — подпись для пустого владельца; `match` — правила «текст владельца → подразделение» (регулярные выражения по порядку, первое совпадение); `official` — переименования в официальные названия |
| `llm` | контекст для ИИ-шлюза: региональные системы, подсказка по целям |
| `method.v2` | признаки стартовых оценок: `externalClient`, `seasonal`, `collectTypes`, `riskTypes`, `goalByCode`, подсказки к критериям |
| `passport` | отраслевые слова для получателя: `labels.business` (как называть бизнес), `recipients` — дополнительные регулярные выражения для `self` (названия самого ведомства, в т. ч. прежние), `federal`, `business`, `regional` и других типов |
| `ui` | заголовок интерфейса, имя файла выгрузки, заголовок анкет |

## rules.json — типы процессов

Список `types` в порядке проверки, первое совпадение выигрывает; `other` — тип по умолчанию.

```json
{
  "key": "grant", "type": "Гранты творческим проектам и НКО",
  "match": { "re": "грант|субсиди", "flags": "i" },
  "hyps": [["Приём заявок формой, автопроверка комплектности", "проверка заявки: часы → минуты"]],
  "simplify": ["Чек-лист комплектности и консультация до подачи", "меньше возвратов заявок"],
  "mvp": "Форма заявки + чек-лист", "tool": "платформа грантов",
  "feas": { "data": 4, "integ": 4, "tech": 4, "mvp": 4, "measure": 4 }, "repeat": 5
}
```

- `match` проверяется по названию, входу и группе процесса;
- `hyps` — стартовые гипотезы улучшения; `simplify` — вариант «упростить или устранить без ИТ»
  (если не задан, берётся общий текст из `lib/hypothesis.js`);
- `feas` — стартовая реализуемость по типу (данные, интеграции, технологии, MVP за квартал, измеримость),
  уровень C — «уточнить»; `repeat` — типовость сценария 1–5.

## functions.json — функции по положению о ведомстве

```json
{
  "npa": { "short": "Положение о комитете", "nav": "Функции комитета", "title": "…", "subtitle": "…", "countII": 6 },
  "tilde": "[а-яёa-z]*",
  "functions": [{ "id": "2.1", "name": "Сохранение объектов культурного наследия", "re": "наследи|памятник", "flags": "i" }],
  "support": { "id": "обесп.", "name": "Обеспечение деятельности", "re": "кадр|бухгалтер|архив", "flags": "i" },
  "interact": { "id": "взаим.", "name": "Взаимодействие с органами власти", "re": "отч[её]т|запрос", "flags": "i" }
}
```

`countII` — число функций раздела положения, чтобы считать долю покрытия реестром. `tilde` подставляется
вместо `~` в регулярных выражениях как окончание слова.

## Необязательные файлы

- `seed.js` — начальная загрузка данных ведомства (`node reestr.js seed`): экспортирует функцию
  `({ ROOT, store, fs, path }) => …`;
- `example.js` — пример реестра для команды `demo` и тестов (как в демо-профиле).

## Что не попадает в репозиторий

`data/` (реестр, факты, карточки, настройки, ключ ИИ-шлюза), `export/` (анкеты, выгрузки, снимки),
`import/` (исходные файлы ведомства), `tests/golden/` (эталон расчётов на данных ведомства).
Профиль ведомства версионируйте отдельно от ядра, если в нём есть фамилии или служебные сведения.

## Проверка

`node reestr.js test` прогоняет ядро на демо-профиле и все файлы `tests/profile-*.test.js` — проверки
установленных профилей ведомств. Для своего профиля добавьте такой файл с проверками подразделений, типов
и функций; если профиля нет, его проверки пропускаются.
