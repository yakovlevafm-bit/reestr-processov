# Методика отбора и оценки процессов

Как инструмент решает, какие процессы брать в оптимизацию и на каком основании. Все пороги — в
`data/config.json` (ключи `cascade`, `v2`), значения по умолчанию — в коде соответствующих модулей.

## 1. Факты и их статусы

Каждое число в оценке — факт с полем источника: количество выполнений в год, активное время на случай,
годовой объём труда, срок, проблемность, формат входа. Статусы:

- `proposed` — из реестра: даёт предварительное значение, диапазон остаётся;
- `verified` — подтверждено экспертом с основанием, периодом и ролью;
- `ai` — предложение ИИ-шлюза: в оценку не попадает, пока человек не подтвердит;
- `rejected`, `superseded` — отклонено, заменено.

Два разных подтверждённых значения одного факта — конфликт; процесс попадает в группу «противоречие».

## 2. Паспорт процесса (`lib/passport.js`)

Вид (основной / обеспечивающий / управления), поток (внутри подразделения / между / межведомственный),
владелец — должность по штату, получатель результата — восемь типов в трёх группах: внешний (граждане,
бизнес, МСУ), органы власти (федеральные, региональные, подведомственные), внутренний. Источник значения:
«реестр», «авто» (разметка по тексту) или «подтверждено» (опросник владельцев, с основанием).

## 3. Отбор по каскаду (`lib/cascade.js`) — основная схема

Шаги идут строго по порядку; процесс останавливается на первом непройденном, и видно почему.

| Шаг | Что проверяется | Решение |
|---|---|---|
| 0 | дубль; «светофор» (зелёный — в норме, красный — устранить или передать функцию); стоп-факторы | отсев с причиной |
| 1 | для кого результат (паспорт) и объём ручного труда: порог 200 ч/год для внешнего получателя и органов власти, 500 — для внутреннего; серая зона 20 % ниже порога проходит с отметкой; значение с поправкой единиц не отсекает | «малый объём» или «сначала замерить объём» |
| 2 | есть ли проблема: анкета (проблемность ≥ 3), ручная оценка риска ≥ 3, СЭД (позже срока ≥ 10 %, прохождение ≥ 5 раб. дн. и вдвое дольше фона подразделения, ≥ 4 уровней резолюций). СЭД подтверждает проблему, но не опровергает | «проблем не выявлено» или «сначала замерить проблему» |
| 3 | поток: межведомственный, передачи между подразделениями | только отметки |
| 4 | реализуемость: владелец подтверждён, размер ≤ 6 мес., базовая линия | отметки; очерёдность |

Очерёдность прошедших: сначала внешний получатель, затем органы власти, затем внутренний; внутри —
по ИП × доверие (раздел 4). План ограничен мощностью команды (чел.-мес. в год); отдельная дорожка
«быстрые победы» для маленьких хорошо автоматизируемых процессов, остановленных на шагах 1–2.

## 4. Оценка v2: ценность, пригодность, размер (`lib/method_v2.js`)

ИП = В × К / Р. В — ценность 20–100 из шести критериев с весами (свой ручной труд, внешняя нагрузка,
связь с целями, качество и правовой риск, срочность, сквозной охват); К — пригодность к автоматизации
0,1–1 (структурированный вход, работа по правилам, стабильность); Р — размер работы 1-2-3-5-8-13.
Каждый критерий — три оценки (мин / вероятное / макс) и уровень доказательности: A — подтверждённый
факт, B — реестр или анкета, C — оценка по типу процесса. Ожидаемое значение — PERT, доверие —
1 / 0,8 / 0,5 по уровням, взвешенное по весам. Используется только для очерёдности внутри каскада.

## 5. Модель доказательств (`lib/maturity.js`)

Уровень зрелости оценки вычисляется, а не назначается:

- **PRE** — допустимы любые оценки, в том числе по типу процесса; для отбора и короткого списка;
- **INTERVIEW** — все критерии оси на уровне A или B; для гипотез и предварительного решения;
- **VERIFIED** — все критерии из подтверждённых фактов, без влияющих конфликтов; для решения о проекте.

Для неполной оси показываются известная часть суммы, покрытие (доля веса критериев) и диапазон при
худших и лучших значениях неизвестных. Ручная оценка — суждение человека с основанием: для зрелости
считается B. Конфликт — два подтверждённых значения или ответ анкеты, расходящийся с подтверждённым;
пока он не разобран, ось выше PRE не поднимается. Ограничение относится к одному критерию-владельцу.
Блокеры — отдельно от баллов: только доказанная невозможность с основанием; низкий балл — не блокер.

## 6. Гипотезы и их реализуемость (`lib/hypothesis.js`)

Ценность — свойство процесса, реализуемость — свойство конкретного варианта улучшения. У каждой гипотезы
свои F1–F5 на 25: данные, интеграции, техническая зрелость, нормативные и организационные ограничения,
измеримость эффекта; свои размер работы и блокеры. Вид гипотезы (упростить без ИТ / по правилам /
интеграция / ИИ-помощник) задаёт стартовые оценки; вариант «упростить или устранить без ИТ» обязателен
и добавляется по типу процесса, если его нет.

Решение по матрице ценность × реализуемость, порог 19/25 по каждой оси, оси не складываются:

| | реализуемость ≥ 19 | реализуемость < 19 |
|---|---|---|
| ценность ≥ 19 | в план — по очереди и до линии мощности | другая гипотеза или сначала снять ограничения |
| ценность < 19 | быстрая победа, если размер ≤ 2; иначе не берём | не берём в этом цикле |
| диапазон пересекает порог | сначала замерить | сначала замерить |

В мощность команды идут размер и чел.-мес. выбранной гипотезы, иначе лучшей по реализуемости без блокеров.

## 7. Короткий список и обзоры эффекта (`lib/cascade.js`, `lib/review.js`)

Короткий список — прошедшие отбор в порядке очерёдности, не больше мощности обследования (по умолчанию
20 за цикл). Ручное включение или исключение — с основанием. Для каждого процесса списка — этапы
обследования: владелец и паспорт, базовая линия, ценность по данным подразделения, не меньше двух
гипотез, реализуемость выбранной. Решение по матрице — когда обследование завершено.

Базовая линия фиксируется при старте проекта: последние подтверждённые факты и показатели СЭД
с источниками; пустая не сохраняется. Обзоры — через 3 и 12 месяцев по тем же показателям; значение
«после» без источника не принимается. Эффект — Δ и % к базовой линии по каждому показателю.

## 8. Методика v1.1 (`lib/method.js`)

Прежняя двухосевая оценка (ценность 5–25, реализуемость 5–25, порог 19) сохранена для портфеля
и совместимости: группы приоритета по границам диапазона, доля подтверждённого веса критериев.

## Источники подходов

WSJF (SAFe), RICE, Standard Cost Model (ОЭСР), TDABC, «Эффективный регион» и стандарт бережливых
проектов органов власти, Methodology v2.0 (двухосевая оценка процесса и гипотезы, null вместо условных
значений, уровни PRE → INTERVIEW → VERIFIED).
